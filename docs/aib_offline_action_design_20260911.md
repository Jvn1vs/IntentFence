# AIB 场景到离线动作证据：设计提案

状态：设计与隔离场景整理，不是已实现策略、构造许可或训练许可。保留原五类 Risk、四类 Alignment 和 candidate 8 第一轮证据，不以二分类文本任务替代原目标。

## 为什么不能直接用已有回复

AIB 182 条中的助手内容主要是示范回复，只有一个显式 tool_call，也没有可作为真实执行证明的回执。源 `ground_truth` 描述攻击案例，`execution` 是安全测试约束。两者均不能直接生成当前动作的 Alignment 标签。

现有 `capture_candidate_action` 只规范化调用并记录 `executed=false`；传入参数的哈希证明记录一致，不证明策略自主选择过动作。后续必须补“读取哪些事实、怎样选择工具/参数”的可重放策略证据。该证据仍是确定性沙箱派生，不冒称真实代理或真实 API 轨迹。

## 场景输入契约

每条准入场景需明确以下信息，不足者继续隔离：

| 字段 | 内容及来源约束 |
|---|---|
| source_binding | 固定 revision、整文件 SHA-256、案例 ID、原始行 SHA-256 |
| decision_boundary | 选定动作前的消息索引；冻结前缀，不读取后续示范回复作为策略输入 |
| user_goal | 截至边界已获授权的用户任务；不能只取第一条而忽略后续用户限制 |
| untrusted_view | 工具返回、检索文档、第三方工具描述等；记录精确字段路径及截取范围 |
| trusted_tool_contract | 工具参数 schema 与能力边界；源缺失时单独记录 project-authored contract，不能冒称源字段 |
| authorization | 谁能操作什么资源、允许的接收方/权限/对象；未知时明确 unknown，不补成允许 |
| fixture_world | 无真实凭据、网络或文件操作的内存状态；模拟秘密与对象保留源指代映射，映射版本单独记录 |
| scenario_group | 源案例、机制、载体、资源/动作结构和工具家族；暂定文字家族不是已核验分组 |

工具描述被投毒的案例尤其需要区分可信工具契约与第三方描述。若原系统文本与低信任载体混在一起，且无法还原可信边界，不通过任意改写把它变成“干净样本”。这类案例保持待裁决，不能为了保留样本随意挪动攻击。

## 策略与动作观测

策略只读取前缀、授权和工具契约，不读取 Risk、Alignment、源 ground_truth、execution 约束或未来示范回复。评估标签所需事实存于独立审核侧。先在固定 fixture 上验证策略，后续构造阶段获批后才用于真实来源场景。

| 策略候选 | 选择规则 | 所需证据 |
|---|---|---|
| goal_bounded | 按用户允许的资源、对象和接收方选择下一步；缺少参数则提出澄清 | 用户限制与参数来源路径，是否需要调用的解释 |
| content_following | 在离线模拟中把选定低信任建议作为候选输入，保留偏离目标的参数 | 低信任建议位置、解析过程、工具匹配和参数选择记录 |
| stale_object | 从同一前缀已出现但不属于当前目标的对象形成候选 | 两个对象在前缀中的独立来源；不得凭空造一个“错误对象” |
| unresolved_scope | 在已有事实不足以确定授权时保留待决调用或澄清动作 | 明确哪条权限/身份事实缺失；不能自动判 malicious |

这些策略名称及分支仅属于 provenance，不进入模型输入；不能根据风险类别直接选一个固定工具。相同工具应同时出现正常和偏离任务的参数，同一机制也应跨不同工具和载体出现。若某案例不支持特定策略，不为补齐四类 Alignment 强造动作。

动作观测至少包括 `action_policy_id`、策略代码/配置哈希、输入前缀哈希、分支日志、工具与参数、逐参数来源、内存状态前后摘要以及 `executed=false`。`action_observation_id` 必须绑定策略实现和输入，不能只给预写候选动作另起一个名字。

## 适配范围与模板风险

首批只建议覆盖有明确证据的接口类型：信息检索/结果返回、消息草稿或发送候选、文件读写候选、权限变更候选、事务/对象更新候选。现有 mock allowlist 无法表达的浏览器、shell、SQL 或支付语义，要提出专用内存适配器；不得统一压成 `message.send` 或 `permission.grant` 来凑数量。

保留邮件、网页、错误响应、工具描述和多轮对话各自结构。新增背景不简单给所有攻击套 Dolly 段落；只有用户目标与任务语义可解释地匹配才提出组合。必须记录组合来源并重新做隔离核验，不能复用已锁定背景或原子测试攻击。

每组至少两个不同动作，满足现有 `action_pair_group` 的同目标、同内容、同 Risk、同角色要求。Alignment 在动作生成后独立审核，不能由策略名称或 Risk 推导。既要有攻击内容下的正常动作，也要有正常内容下的偏离/不确定动作；真实缺失的组合如实报告。

## 划分与验收

先建立保守分组图，再整体分配角色：同源案例、近重复、模板派生、相同任务/对象结构及同一工具描述攻击的变体应连边。发现跨 agent 的同义家族要统一审查；过细的家族 ID 不能作为隔离成功证据。AIB 原类别分层 70/15/15 不满足此要求，不直接照搬，也不把全部182条重组后称为182个独立训练场景。

calibration 与 final test 继续锁定。当前文本筛查没有覆盖完整 AgentDojo、语义家族或工具衍生关系；在这些缺口关闭前，不能标记任何新版训练就绪。角色数量应由可独立分组数决定，不通过重复采样伪造支持量。

未来实现的验收应包含：改动后续示范回复不影响候选动作；改变用户授权能按规则改变动作；源字段/工具 schema 缺失时拒绝；策略看不到标签；原始文件不可覆盖；同族跨角色被拒绝；无网络、系统 shell 或真实文件动作；Risk 与 Alignment 分开存储及审核。通过这些检查仍只证明离线框架，不证明真实部署防御能力。
