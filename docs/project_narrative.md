# IntentFence 项目叙事记录

状态：叙事草稿，供后续项目介绍、简历和研究汇报使用。本文只记录已经发生的事实与明确的下一步计划，不把计划写成实验结果。

## 一句话版本

IntentFence 从一个受控合成数据上的工程基线开始，先完成可审计的数据、训练和安全评测管线；第一轮训练暴露出模板化数据可能带来的分布单一问题，下一步将引入许可证清晰的多来源公开训练数据和更丰富的 hard negatives，用跨来源评测检验泛化能力。

## 项目经历版本

我搭建了 IntentFence，一个面向间接提示注入和任务对齐风险的轻量级检测研究原型。项目先使用 project-owned mock scenarios 建立严格的数据 schema、来源追踪、去重、隔离划分、审核记录、训练授权和可复现运行 manifest，并冻结 calibration 与 final-test 边界。

在 candidate 8 的 `B-ai-assisted-engineering` 路线上，我完成了第一轮 Base C multitask、seed 42 工程训练。该轮使用 5,000 条 train 和 2,000 条 validation 数据，运行 5 个 epoch，Validation Risk Macro-F1 为约 0.9995，成功完成 checkpoint reload 和运行记录生成。这个结果只证明工程管线能够运行，不是论文级结果，也不是对真实攻击防御能力的证明。

第一轮结果同时暴露了数据设计上的重要风险：训练和验证数据来自受控、模板化的合成场景，模型可能依赖构造模式而不是学习可迁移的安全语义。因此，项目下一阶段不是简单扩大同类模板，而是建立 candidate 9：保留 candidate 8 作为历史工程基线，加入许可证清晰的公开训练数据、不同任务结构、不同攻击表达和 hard negatives，并按来源、模板和近重复关系重新隔离 train/validation/calibration/test。

最终要验证的问题是：增加数据来源和表达多样性后，模型能否在未参与训练的外部来源上保持安全性，同时降低对正常安全讨论文本的误报。只有在跨来源、独立测试和完整可复现记录都支持时，才能声称数据多样性改善了泛化；否则就如实报告为一次失败分析或边界发现。

## 后续故事线

### 2026-09-09 已发生的数据迭代（尚无新模型结果）

公开数据扩充时发现，InjecAgent 的原子攻击和用户指令均被官方测试复用，重新组合不能提供独立训练证据，因此将其保留为外部评测。最初的 BIPIA 扩充又因旧测试隔离而几乎只剩表格背景。项目据此增加了经所有者批准、保留 CC-BY-SA-3.0 归属的 Dolly 人工问答/摘要/信息抽取背景。

v3 已构造 20691 条配对样本，包含 4579 个背景/近重复组，训练部分不再几乎全是表格。这是数据构造进展，尚未完成训练或证明效果提升；攻击表达多样性、困难负样本和独立多任务标签仍有缺口。详细证据见 `reports/data/candidate_9_v3_build_20260909.md`。

项目所有者明确决定继续补齐五类风险、独立四类任务对齐和可追溯动作数据，保持原动作感知多任务目标。Dolly 解决的是背景来源的一部分缺口，不能替代动作观测与安全标签审核。

2026-09-10，进一步下载并审计 ToolSafety 固定训练数据快照，发现论文计数与发布快照不同，且只有部分对话包含工具返回后的调用。项目据实际文件哈希、字段与调用解析结果记录可用性，并保留格式异常和未明归属的记录待查，没有把公开数据整包直接加入训练。此时仅完成结构审计，尚无新增模型训练或效果结论。

1. 记录第一轮基线的高分与模板化风险。
2. 审核公开数据源、许可证、隐私和可用 split。
3. 构造 candidate 9 的多来源训练集与 hard negatives。

## 可使用的短句

2026-09-11，完成公开动作来源 200 条完整上下文 AI 预审：内容 Risk 暂定均为 benign，动作对齐为 112 条 aligned、86 条 ambiguous、2 条 unrelated。复核发现工具默认参数覆盖已查询的对象、同一 ID 对应不同商品、以及助手补写用户未提供的信息。公开来源并不自动消除模拟和模板问题，也不能仅因工具调用看似相关就认定任务对齐。因此项目保留逐条依据与不确定意见，分别判断内容风险、动作对齐和可执行性，未为了补齐攻击类别强行贴标签。此次是数据质量发现，尚未证明训练收益；多 agent 分工不等同双独立审核或人审。详见 `reports/data/toolsafety_prefix_pre_review_20260911.md`。

> 第一轮工程基线在受控合成数据上取得了很高的验证分数，但这也提示模板化数据可能造成分布偏移和虚高评估。项目随后转向多来源、许可证清晰的数据构造与跨来源评测，重点检验模型是否学到可迁移的安全语义，而不是记住单一模板。

### 2026-09-11：攻击场景不等于动作训练证据

新增 AgentInjectionBench 的只读审计验证了 182 条公开案例，但其中只有一条显式工具调用，且为正常用户请求后的操作。9 条 AI 抽查显示攻击场景通常配有安全响应示范；直接将 unsafe 场景标签赋给助手动作会造成错误监督。项目据此把公开场景保留为隔离素材，先补授权边界、场景家族与可追溯动作证据，而没有为了数量直接纳入训练。这是数据设计改进依据，尚无新增模型效果结论。

全量场景整理进一步确认，182条公开案例能提供五类风险的暂定语义线索，但现有动作证据不足，且不同来源分类无法直接映射本项目标签。项目因此提出保留原载体、逐参数追踪来源、独立判断动作对齐的离线构造方案；这仍是设计进展，不是新增训练样本或模型收益。整理得到112个暂定家族名，尚需保守归并，不能以家族名称数量包装数据多样性。

随后实现了仅使用合成 fixture 的离线动作选择框架：按用户授权或低信任字段解析参数，保留逐字段来源、策略分支和代码/输入哈希；相同工具可以产生符合目标或偏离目标的候选参数。授权未知、源字段缺失和不支持的接口不会通过猜测补齐。这个阶段解决的是动作构造的可追溯性，尚未生成真实来源训练样本，固定规则的模拟提案也不等同于真实代理轨迹；四类 Alignment 仍需独立审核。

在少量真实来源适配中，四个 AIB 场景产生五条隔离动作提案，另两个候选因笔记标题/文件路径语义不同、邮件正文缺失及 BCC 接口不足而排除。试点发现，公开数据的自然语言建议不能直接套用 fixture 的 JSON 接口；项目保留原消息，将 AI 的字段解释单独记录并绑定源行和字符位置。一个文件场景形成同内容不同路径的对照，但攻击 key 本身含省略号，因此没有将写入提案包装为可成功执行的攻击。这是构造可行性与数据缺口的证据，尚未获得独立 Alignment 或训练收益。
