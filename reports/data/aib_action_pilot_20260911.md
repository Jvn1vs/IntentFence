## 如何绑定，哪些解释仍由 AI 提供

配置：`configs/aib_action_pilot_20260911.yaml`。隔离准备记录：`data/interim/aib_action_pilot_20260911/preparation.json`。构造入口：`scripts/build_aib_action_pilot.py`，只读校验入口：`scripts/verify_aib_action_pilot.py`。

所有四例的源 conversation 边界为前两条消息，即 user + tool_result，后续 assistant 示例不进入策略。另原样保留 system_prompt，形成三个消息的策略 prefix；回执记录索引映射和原工具名称。整行哈希采用原 UTF-8 行字节（不含换行），不是重新序列化 JSON 的哈希。原 tools_available 绑定哈希且保留于原始数据，不作为自动可信契约或可执行代码。

为解决 fixture-only 参数全部要求来自 user 的限制，增加显式 `SourcePreparation`：逐参数标明当前用户请求的授权解释、事实来源和 AI 理由。源参数可来自工具返回，但授权解释仍绑定当前 user；不把低信任内容本身当作授权。旧 fixture 模式保留原限制，源模式必须显式使用 `quarantined_source_pilot`。

自然语言攻击没有被改写成 JSON 消息。00178 的参数映射独立存放在 AI 准备记录中，策略日志明确是“解析 AI 准备的源 span”，不是自动理解自然语言。选择逻辑对这份准备记录可重放，但适配器无法独立证明准备者的语义判断正确；工具类别和事实范围仍由 AI 选择。这一试点验证的是来源绑定与有限构造可行性，不足以解决统一模板问题或证明真实代理行为分布。
